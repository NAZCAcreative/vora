# 모바일 UI 점검

## 적용 범위

- 공통 본문 15px/22px, 입력 16px, 보조 텍스트 최소 12px. 글꼴 토큰만 사용하던 화면에도 기본 크기 적용.
- 상단 64px, 중앙 로고 폭 96px, 공통 상단 버튼 터치 영역 44px. 모바일 설정 버튼은 왼쪽에 배치해 로고와의 겹침 방지.
- 하단 메뉴와 고정 CTA에 동일한 안전 여백 기준 적용. html/body의 중복 80px 여백 제거.
- 모바일 채팅 FAB를 숨겨 예약·결제·저장 CTA와 충돌 방지. 하단 채팅 탭 유지.
- 랜딩에서 설명과 시작 버튼을 이미지보다 먼저 배치. 온보딩 이미지 크기와 하단 간격 조정, 단계 이동 버튼 터치 영역 확대.
- 로그인·회원가입 폼 좌우 여백, 필드 높이, 버튼 및 브랜드 색상 정리.
- 검색 카드의 찜·프로필·예약 액션 및 필터 터치 영역 확대. 검색 화면의 중복 하단 여백 제거.
- 학생 결제 화면의 중복 고정 상단 영역을 일반 흐름으로 변경.
- 교사 통계 카드 간격 및 모드 전환 줄바꿈 개선. 학생·교사 채팅 입력 컨트롤 크기 조정.
- 닫힌 알림·채팅 패널을 visibility로 숨겨 보이지 않는 컨트롤의 키보드 접근 방지.
- 키보드 포커스 표시, reduced-motion 지원, viewport-fit 및 키보드 viewport 설정 추가.

## 검증

- TSX 50개 정적 검색: 8~11px 명시 텍스트와 빈 `href="#"` 없음.
- Chromium: `/`, `/login`, `/signup`, `/register`, `/onboarding`, `/student/search`, `/support`를 320/375/390/768/1440px에서 확인. 35개 조합 모두 HTTP 200, document 가로 넘침 없음.
- 375px 캡처를 통해 로그인·온보딩·검색 화면을 육안 확인.
- 온보딩 마지막 단계 이동, 알림 열기와 Escape 닫기, 검색 필터 펼치기 통과. 상단 sticky 높이 64px 확인. 하단 높이 변수를 114px로 변경했을 때 반영 확인(실기기 safe-area 검증과는 별개).
- `npm run type-check` 통과.
- `npm run lint` 오류 없음. 기존 hook dependency, 이미지 및 외부 폰트 관련 경고 5개 존재.

## 검증 한계와 후속 확인

- 로그인 보호 화면은 코드 기준 점검 및 공통 스타일 적용. 실제 계정으로 예약·결제·교사 관리·정산을 끝까지 실행한 것은 아님.
- 긴 사용자 이름, 실제 첨부파일 및 많은 채팅 메시지 데이터로 계정별 추가 확인 필요.
- iOS 실기기에서 소프트 키보드와 safe-area 동작 확인 필요. 데스크톱 Chromium의 모바일 크기 검사는 이를 완전히 대체하지 않음.
- 기존 준비 중 기능(약관 상세, 일부 첨부/메뉴 액션 등)은 이번 UI 간격 작업에서 서비스 기능으로 구현하지 않음.

검수 캡처와 임시 스크립트는 Git 제외 경로 `.tmp/ui-audit/`에 저장.
