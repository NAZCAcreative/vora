# 관리자 페이지

학생·선생님 **마이페이지 맨 위 → 관리자 페이지**에서 접근합니다. 주소는 `/admin`입니다.

## 접근 권한

- 현재 박대건 계정 ID `3429c1b9-9b35-45dd-87fb-64fccf769a9a`만 허용합니다.
- 이름 또는 `profiles.role` 값으로 접근 권한을 판단하지 않습니다. `admin_members` 테이블에 등록한 ID와 인증된 `auth.uid()`를 비교합니다.
- 서버 레이아웃이 로그인과 관리자 권한을 확인하고, 모든 관리자 RPC가 다시 권한을 확인합니다. 비로그인은 로그인으로 이동하고, 다른 로그인 계정은 관리자 페이지에서 404 처리합니다.
- `admin_members`, `admin_profile_notes`, `admin_audit_logs`는 RLS를 활성화하고 일반 클라이언트의 직접 접근을 회수했습니다. 관리자 권한 부여 버튼은 제공하지 않습니다.
- 선생님 인증 상태를 직접 REST로 변경해 셀프 인증하는 경로도 DB 트리거에서 차단했습니다.
- 앱 런타임에는 서비스 키나 관리 토큰이 필요하지 않습니다. 사용자 세션으로 검증된 DB 함수만 호출합니다.

## 화면과 기능

- 운영 현황: 회원, 학생, 선생님, 수업 상품, 신규 가입, 인증 검토, 결제 대기, 정산·출금, 낮은 평점 리뷰, 사진 누락, 통화별 결제·환불 집계.
- 회원 관리 메뉴 안의 전체 회원 / 학생 / 선생님 탭: 이름·이메일·ID·소개·전문 분야 검색, 상세 프로필, 회원 정보 수정, 비공개 관리자 메모. 이메일은 상세에서 확인하며 목록에서는 생략합니다.
- 선생님 심사: 대기 / 보완 요청 / 승인 / 반려. 보완·반려에는 선생님에게 보여줄 안내가 필수이며, 관리자 내부 메모는 별도로 저장합니다. 승인 여부와 기존 인증 배지를 같은 트랜잭션에서 갱신합니다.
- 선생님 마이 상단에서 심사 안내를 확인하고 보완·반려 후 재심사를 요청할 수 있습니다. 신규 선생님은 자동으로 대기 상태로 등록되며 기존 인증 선생님은 승인 상태로 이관했습니다.
- 신고·문의: 접수 / 처리 중 / 처리 완료, 접수자·가입 역할·유형·분야 표시, 내용 검색, 상태·날짜·회원 필터, 공개 답변과 비공개 내부 메모 저장. 답변 없이 처리 완료할 수 없습니다. 운영 현황에서 새 접수와 처리 중 건수로 바로 이동합니다.
- 고객센터 `/support`: 로그인 회원이 문의·신고를 접수하고 본인 내역·답변을 10건 단위로 조회합니다. 접수 요청 ID로 네트워크 재시도 중복을 막고 회원별 시간당 10건 제한을 적용합니다. 답변은 고객센터에서 확인하며 외부 메일·문자를 발송하지 않습니다.
- 학생은 학생 역할 또는 수강 이력이 있는 회원, 선생님은 teacher_profiles가 있는 회원입니다. 한 회원이 양쪽에 포함될 수 있습니다.
- 회원 상세에서 해당 회원의 수업·예약·결제·정산·출금·리뷰·관리 이력으로 이동할 수 있습니다.
- 수업 상품: 선생님, 유형, 가격, 정원 확인과 공개·비공개 변경.
- 수업 일정 / 예약: 일시, 참여 인원, 선생님·학생, 처리 상태 조회.
- 결제 / 정산 / 출금: 저장된 처리 상태와 금액 조회. 통화는 구분하며 계좌번호는 끝 4자리만 노출합니다. 실제 결제 취소나 송금, 지급 상태 변경은 이 화면에서 실행하지 않습니다.
- 리뷰: 낮은 평점 및 답변 상태 필터, 리뷰·답변 전문 확인.
- 쿠폰: 할인 조건·등록 수·만료일 확인, 사용 허용·중지.
- 관리 이력: 관리자, 대상, 사유, 변경 전후 값 기록 및 조회.

모든 목록은 DB에서 10·20·50개 단위로 조회합니다. 최신 생성일과 고유 ID로 정렬하고, 마지막 페이지를 넘는 요청은 보정합니다. 검색·상태·날짜·회원별 필터와 페이지를 URL에 유지합니다. 날짜는 한국 시간의 **등록·생성일** 기준이며 종료일 전체를 포함합니다. CSV는 현재 페이지 데이터만 내보내고 수식으로 해석될 수 있는 셀을 이스케이프합니다.

변경은 사유를 입력한 후 저장합니다. DB에서 기존 값을 잠그고 화면에서 읽었던 값과 대조한 뒤 수정과 이력 기록을 하나의 트랜잭션으로 처리합니다. 충돌하면 새로 조회하도록 안내합니다.

## DB와 검증

마이그레이션: `supabase/migrations/0011_admin_console.sql`, `0012_review_support.sql` (연결된 프로젝트에 적용 완료).

`teacher_applications`, `support_tickets`는 일반 클라이언트의 직접 접근을 차단하고 RPC로만 접근합니다. 본인 조회는 인증된 ID를 DB에서 확인하며 내부 메모 필드를 반환하지 않습니다. 기존 인증 토글 함수의 직접 실행 권한을 회수하고 심사 경로로 통합했습니다. 재심사 요청도 작업자와 전후 상태를 관리 이력에 기록합니다.

SQL 검증: `supabase/tests/admin_console.sql`. 관리자/비관리자 인증 문맥, 전체 목록, 페이지 중복·상한 보정, 검색·필터, 회원 수정·인증·공개·쿠폰·메모, 동시 수정 충돌, 이력 기록을 검증하고 **롤백**합니다. 테스트 데이터와 관리 이력은 실제 운영 데이터에 남지 않습니다.

```sh
# SUPABASE_ACCESS_TOKEN은 환경변수 또는 stdin으로만 전달합니다.
node scripts/supabase-query.mjs supabase/tests/admin_console.sql --apply
node scripts/supabase-query.mjs supabase/tests/review_support.sql --apply
npm run type-check
npm run lint
```

실제 브라우저에서 비로그인 관리자 접근 차단을 확인했습니다. PC(1440px)·모바일(390px) 관리자 레이아웃은 가상 데이터 정적 렌더링으로 확인했습니다. 관리자 자동 로그인 방식의 브라우저 테스트는 자동 승인 검토에서 차단되어 수행하지 않았으며, 실제 관리자 기능의 권한·저장은 DB 테스트로 검증했습니다.

참고: [Supabase 함수 권한과 search_path](https://supabase.com/docs/guides/database/functions), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
